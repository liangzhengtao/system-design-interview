## Reporting a Vulnerability / 报告漏洞

This is an educational repository. If you find any security concerns related to the content or infrastructure:

这是一个教育性质的仓库。如果你发现与内容或基础设施相关的安全问题：

### For Content Issues / 内容问题

If you find inaccurate or potentially harmful technical content:

如果发现不准确或可能有害的技术内容：

1. Open an issue with the label `security-content`
2. Describe the inaccuracy and provide correct information
3. We will review and update within 48 hours

### For Infrastructure Issues / 基础设施问题

For issues with the repository infrastructure (GitHub Actions, etc.):

1. **Do NOT** open a public issue
2. Email the maintainers directly
3. Include a description of the vulnerability
4. Include steps to reproduce if applicable

## Response Timeline / 响应时间

- **Acknowledgment**: Within 48 hours
- **Initial assessment**: Within 1 week
- **Resolution**: Depends on severity

## Scope / 范围

This policy covers:

- Repository content accuracy
- GitHub Actions workflows
- Repository configuration

This policy does NOT cover:

- The actual system designs (these are educational, not production code)
- External links referenced in the content

## Security Proven Patterns / 安全最佳实践

When contributing system design content:

贡献系统设计内容时：

- Do not include real API keys, passwords, or credentials in examples
- Use placeholder values like `YOUR_API_KEY` or `example.com`
- Do not reference internal company systems or architectures
- Keep capacity estimates as educational examples, not real production data

感谢你帮助保持这个项目的安全和准确。
